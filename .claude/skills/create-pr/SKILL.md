現在のブランチの変更内容でPRを作成する。起動後は途中で確認を挟まず最後まで実行してよい。
ただし前提条件を満たさない場合は例外で、PRを作成せずに状況をユーザーへ伝えて終了する。
指示がないのにコミットやpushを始めてはいけない。

## 前提条件の確認

1. `git branch --show-current` が `main` なら、作業ブランチを切るよう伝えて終了する
2. `git status --porcelain` に出力があれば、未コミットの変更はPRに含まれないことを伝えて終了する
3. `git status -sb` の先頭行で upstream の有無と `ahead` を確認する。upstream が無い、または `ahead` があれば、pushが必要なことを伝えて終了する
4. `gh pr view --json number,url` で現在のブランチのPRを確認する。存在すれば新規作成せず「更新」に進む

## 手順

1. `git log main..HEAD --oneline` と `git diff main...HEAD` を通しで読む
   - デバッグ用のログ、コメントアウトした不要コード、意図しないファイルの混入を確認する
2. `.github/pull_request_template.md` の各セクションを埋めて本文を作る
   - HTMLコメント（書き方のガイド）は削除せずそのまま残す
   - 埋められないセクションは空欄にせず「特になし」と明示する
   - 紐付けるissueが無い場合は `Closes #` の行を削除する
3. 本文を一時ファイルに書き、`gh pr create --base main --title "<タイトル>" --body-file <ファイル>` で作成する
4. 作成したPRのURLをユーザーに伝える

## 更新

PRの本文は、そのブランチの最新のコードを説明していなければならない。次のときに更新する。

- 既存のPRがある状態でこのスキルを起動したとき
- PRがあるブランチにpushした直後。pushを指示された作業の続きとして、改めて指示を待たずに行う

手順:

1. `git log main..HEAD --oneline` と `git diff main...HEAD` を読み直す。前回読んだときの記憶で済ませない
2. `gh pr view <番号> --json title,body` で現在のタイトルと本文を取得し、セクションごとに差分と照合する
   - タイトル: 変更の主眼が変わっていないか
   - 背景 / なぜ: 方針転換があれば理由を書き換える
   - 何をしたか: 追加・削除・作り直した変更が反映されているか
   - 確認方法: コマンドの出力やCIの結果は、最新のコミットに対して実行したものだけを残す。
     差分が変わったのに前回の結果を残さない。再実行していない項目はチェックを外す
   - レビューで見てほしい点: 解消した論点は消し、新たに迷った箇所を足す
3. 食い違いがあれば `gh pr edit <番号> --title "<タイトル>"` や `gh pr edit <番号> --body-file <ファイル>` で修正する。
   無ければ更新せず、照合した範囲と結果をユーザーに報告する
4. 古くなった記述は「追記」で残さず消す。本文は変更の履歴ではなく、現在の状態の説明にする

## タイトル

Conventional Commits形式。`修正` `update` `WIP` のような中身の分からないタイトルにしない。

```text
feat(auth): Google OAuthログインを追加
fix(api): ユーザー取得時のnull参照を修正
```

## 本文の方針

- 「何を変えたか」より「なぜ必要か」を厚く書く。diffを見れば分かることを繰り返さない
- 「何をしたか」は3〜5点の箇条書き。diffを読まずに全体像がつかめる粒度にする
- 「確認方法」には実際に実行したコマンドと結果を書く。実行していない項目にチェックを入れない
- 判断に迷った箇所・代替案を検討した箇所は「レビューで見てほしい点」に必ず書く
- `Closes #N` は、対応するissueが確実に分かる場合のみ記載する
- 破壊的変更がある場合は、影響範囲と移行手順を本文の冒頭に明記する
